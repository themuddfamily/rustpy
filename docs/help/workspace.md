# Workspace settings

Settings search, page breadcrumbs and modified-page indicators help locate an
option. Apply persists the current settings; Cancel restores the dialog snapshot.
Reset and defaults have different scopes. Default-new-project settings do not
retroactively rewrite every existing project. Settings Sync deliberately separates
shareable preferences from credentials, trust, absolute local paths and machine
state. Inspect the preview/conflicts before importing or synchronizing.

Tool windows can move between sides/slots, resize, maximize, float or use a native
window where supported. Pinned and unpinned/autohide behavior differ. Named layouts
capture placement and visibility; restoring a layout does not start the processes
whose views it contains. Hide All and Restore/Last recover visibility without
terminating owned jobs. Tool-window tabs support their own pin/close/group actions.
The Services view is another view of owned work, not an independent owner.

Settings › Appearance and the customizable toolbar/status controls affect window
chrome; Settings › Editor affects document presentation and behavior. Accessibility,
locale, Unicode input and font availability are platform-specific. Natural Languages
controls proofreading and language preferences; bidi and grapheme-aware movement
must preserve original source rather than normalize it silently.

Settings › Keymap selects a parent map, searches actions and edits bindings,
including chords. Resolve reported conflicts in the active context. See the
[keymap reference](../keymap.md). Find Action shows current effective bindings.
Plugins can contribute settings/actions/resources and, when explicitly supported
and granted, executable capabilities. Installation and signatures are not a blanket
permission to read files, execute commands or contact networks. Inspect capability
grants and trust decisions. Optional modal-editing bindings remain separate from
the ordinary editor keymap.
