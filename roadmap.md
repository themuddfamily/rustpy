# RustPy feature roadmap

This is RustPy's feature list, grouped by area and ordered into delivery phases. It records
what the IDE does and how complete each feature is, and it is the reference for progress
tracking: source comments cite items as `roadmap §x.y`.

Legend: `[ ]` not started · `[~]` partial (implemented, with the remaining gaps noted) ·
`[x]` done (implemented and tested)

Each top-level section maps to one or more crates in the Cargo workspace (see §0.1). Item
descriptions list the sub-features in scope; a trailing `?` marks an idea that may be dropped,
and *(N/A)* marks an entry that has no meaningful equivalent in a native Rust IDE and is
listed only for completeness. The overall verification state is summarised in
[HANDOFF.md](HANDOFF.md) and the change history is at the end of this file.

---

## Delivery phases

| Phase | Theme | Goal |
|------:|-------|------|
| 0 | Foundation | Workspace, text buffer, Python lexer/parser, GUI shell that opens a folder and edits files |
| 1 | Editor parity | Every editing, navigation-in-file, find/replace, highlighting and folding feature of the editor |
| 2 | Python intelligence | Resolver, type inference, completion, inspections, intentions, navigation, refactorings, formatter, docstrings |
| 3 | Run / Debug / Test | Run configurations, run console, DAP debugger (debugpy), test runner UI, coverage |
| 4 | Version control | Git (log, commit, branches, diff/merge, blame, shelve, rebase), local history |
| 5 | IDE shell & settings | Settings dialog, keymaps, themes, tool-window docking, Search Everywhere, project wizard, plugins |
| 6 | Tools | Terminal, Python console/REPL, packages tool window, interpreters, markdown, TODO, bookmarks, structure, hierarchy |
| 7 | Frameworks & integrations | Frameworks (Django/Flask/FastAPI/Jinja), databases, HTTP client, Jupyter, SciView, Docker, remote, profiler |
| 8 | Platform & distribution | CLI launcher, installers, i18n, accessibility, performance, crash reporting |

## 0. Foundation & architecture

### 0.1 Workspace layout
- [x] Cargo workspace with one crate per subsystem:
  - `crates/rustpy-text` — rope text buffer, positions/offsets, edits, transactions, undo tree, line endings, encodings
  - `crates/rustpy-syntax` — Python lexer, parser, lossless CST + AST, error recovery, incremental reparse
  - `crates/rustpy-semantic` — scopes, name resolution, imports, type inference, stubs/typeshed, project index
  - `crates/rustpy-analysis` — inspections, intentions/quick-fixes, code cleanup, duplicate detection
  - `crates/rustpy-templates` — live templates, surround templates, postfix completion (completion ranking lives in `rustpy-semantic`)
  - `crates/rustpy-refactor` — rename, extract, inline, move, change signature, safe delete, pull/push members
  - `crates/rustpy-format` — formatter (PEP 8 code style engine), import optimizer, rearranger, EditorConfig
  - `crates/rustpy-highlight` — syntax/semantic highlighting for Python and bundled languages
  - `crates/rustpy-project` — project model, `.idea`-like persistence, interpreters/SDKs, packaging tools, run configs
  - `crates/rustpy-run` — process execution, consoles, test runners (pytest/unittest/doctest), coverage, profiler
  - `crates/rustpy-debug` — Debug Adapter Protocol client for debugpy, breakpoints model, frames/variables
  - `crates/rustpy-vcs` — Git (libgit2 + CLI), local history, diff/merge algorithms, blame, shelve
  - `crates/rustpy-search` — find in files, usages, structural search, scopes, regex engine glue
  - `crates/rustpy-terminal` — PTY management and VT emulation for the embedded terminal
  - `crates/rustpy-console` — Python interactive console backend (REPL protocol, variables, IPython)
  - `crates/rustpy-settings` — settings schema, persistence, keymaps, color schemes, code style schemes
  - `crates/rustpy-ui` — egui/eframe front-end: editor widget, tool windows, dialogs, popups, status bar
  - `crates/rustpy-lsp` — optional LSP server exposing the engine to other editors
  - `crates/rustpy/src/main.rs` — the `rustpy` binary (IDE launcher + CLI subcommands)
- [x] Shared `rustpy-core` utilities: file IDs, VFS abstraction, cancellation tokens, background task scheduler, event bus
- [x] Virtual file system with change watching (notify), external-change detection and reload prompts
- [x] Persistent caches / indexes with invalidation ("Invalidate Caches")
- [x] Logging (`rustpy.log`), diagnostics bundle, crash reporting hooks
- [x] CI: `cargo fmt`, `cargo clippy -D warnings`, `cargo test`, headless UI smoke test — strict formatting, locked Clippy/tests, explicit desktop launcher build and Xvfb smoke; existing formatting debt cleared

## 2. Python language intelligence

### 2.1 Lexer & parser (`rustpy-syntax`)
- [x] Tokenizer: full Python 3.8–3.14 token set, INDENT/DEDENT, NEWLINE/NL, implicit line joining, backslash continuation, string prefixes (`r b u f t` combos), f-string tokenization per PEP 701 (nested quotes, `=` debug specifier, format specs, `!r/!s/!a`), t-strings (PEP 750), bytes, numeric literals (underscores, imaginary, hex/oct/bin), soft keywords (`match`, `case`, `type`, `_`), walrus, `->`, `**=`, `@=`, `:=`, `...`, encoding cookie, type comments, non-UTF-8 handling, tab/space inconsistency detection, unterminated strings recovery
- [x] Recursive-descent / PEG-compatible parser producing a **lossless CST** (every token and trivia kept) and a typed **AST** view: modules, statements (simple & compound), expressions with full precedence, `async` constructs, `match` patterns (literal, capture, wildcard, value, group, sequence, mapping, class, OR, AS, star), decorators, lambda, comprehensions (incl. async), star-expressions, slices, `yield`/`yield from`/`await`, `global`/`nonlocal`, `del`, `assert`, `with` (parenthesized items), `try`/`except*`, `type` aliases and PEP 695 type parameters (incl. defaults PEP 696), positional-only `/` and keyword-only `*`, annotations and annotated assignment, return annotations, f-string ASTs, `print` statement detection for Py2 diagnostics
- [x] Error recovery: produce best-effort tree with error nodes and precise diagnostics (unexpected indent, unindent mismatch, missing `:`, unclosed bracket, invalid syntax with hints like "did you mean `==`?", "expected expression"), never panic on any input (fuzzed) — corpus-checked: no false errors on ~124k files CPython accepts (stdlib 3.12/3.13/3.14 incl. test suites, 115k third-party files), no panics on 33k mutated files, bounded nesting
- [x] Incremental re-parse on edit (reuse unchanged subtrees), parse timings suitable for 100k-line files — `rustpy_syntax::reparse`: single-token, statement-run and full strategies, results identical to a full parse (exhaustive small-edit and fuzz tests against full parses), used by the editor and the analysis database; a 100k-line file parses in ~80 ms
- [x] Syntax tree query API: node kinds, parent/child/sibling traversal, text ranges, find node at offset, `PsiElement`-like utilities (enclosing function/class/statement/expression), comments & docstring attachment
- [x] Language level per interpreter (3.8 … 3.14): version-gated syntax diagnostics ("match statement requires Python 3.10") — PyCompatibility inspection follows the selected interpreter version
- [x] Parser for `.pyi` stubs, `requirements.txt`, `pyproject.toml` (TOML), `setup.cfg`/INI, `.editorconfig`, `.env`, Django templates/Jinja2, reStructuredText & Markdown (lightweight), regex dialect (for injections), JSON/YAML (for data files)
- [x] Round-trip CST printer (used by refactorings and formatter to re-emit code with comments/trivia preserved)
- [x] Golden-file tests against CPython's `ast` module output for the whole stdlib — complete official CPython 3.12.3 Lib corpus: all 1,774 Python files, including 1,019 test modules and all nine primary rejections; maintained reproducible preparation and exact AST-field comparison scripts

### 2.2 Semantic model (`rustpy-semantic`)
- [x] Module index: discover modules from project content roots, source roots, interpreter paths (`sys.path`, site-packages, `.pth` files), namespace packages, `__init__.py` packages, binary modules (`.so/.pyd`) via generated skeletons/stubs, `__all__` evaluation, relative/absolute import resolution, conditional and `try/except ImportError` imports, `importlib`/`__import__` best-effort, user-added roots, excluded folders
